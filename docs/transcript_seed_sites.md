# Transcript seed-site discovery

`sirnaforge.core.transcript_seed.scan_transcript_seed_sites` discovers canonical sites in transcript-oriented cDNA for a supplied set of siRNA guide sequences. It is a separate evidence channel from the known-miRNA seed resemblance scan: a result describes a complementary sequence site in a transcript and makes no claim that a miRNA binds it.

The guide's 5′ positions 2–8 define the seed. Target strings are normalized to uppercase DNA alphabet (`U` becomes `T`), then compared in transcript 5′→3′ orientation against the reverse complement of guide positions 2–7 or 2–8. The scanner reports 6mer, 7mer-A1, 7mer-m8, and 8mer geometries. Site identity is guide, transcript, scope, and the target anchor complementary to guide positions 2–7. Overlapping class motifs sharing that core anchor describe one site; the strongest class is retained in the order 8mer, 7mer-m8, 7mer-A1, then 6mer. `seed_core_start`/`seed_core_end` identify that anchor, while `start`/`end` span the retained motif.

`TranscriptSeedTranscript` requires full cDNA and can carry an explicitly annotated 3′UTR sequence plus its 1-based `utr3_start` coordinate. Full-cDNA scans search the complete supplied sequence. 3′UTR scans search only this explicit sequence and return coordinates in the full transcript. A missing sequence or start coordinate marks that transcript unavailable for UTR analysis; an explicitly empty UTR is available and has no sites. UTR text must match its stated interval in the full cDNA. Ambiguous bases and mismatched intervals fail explicitly.

Summary schema version 2 records the site-identity version. Workflow collection ignores summaries with a different or missing identity, so counts made with older site-deduplication semantics cannot satisfy current limits.

`TranscriptSeedScanResult` includes site, transcript, resolved-gene, and unresolved-gene counts. An unresolved gene is a transcript with at least one site and no `gene_id`; unavailable transcripts are listed separately and are not counted as scanned. The API performs sequence-site discovery only; later evidence and intent policy layers decide how, if at all, these sites affect candidate ranking or filtering.

The workflow's opt-in channel is `--transcript-seed-species human,mouse`; it reuses each requested species' materialized full cDNA reference, including transcripts outside the target gene. `--transcript-seed-required-species` marks the subset needed for qualification; other requested species are exploratory. `--transcript-seed-scope three_prime_utr` requests UTR-only scanning. The workflow currently materializes cDNA FASTA without UTR features, so those transcript observations are reported unavailable rather than as zero-site passes. The lower-level producer can consume an explicit UTR annotation manifest when one is supplied by a future reference integration. `--max-transcript-seed-sites` adds a per-guide ceiling over completed required species.

For independent per-species limits, `--species-liability-limits` accepts ceilings for transcript-seed sites, transcripts, and resolved genes alongside transcriptome mismatch ceilings. For example, `'{"human":{"transcript_seed_sites":100,"transcript_seed_transcripts":40,"transcript_seed_genes":10,"action":"fail"},"mouse":{"transcript_seed_sites":300,"action":"warn"}}'`. These numeric limits are supplied by the run; none are universal defaults. A gene count marked as a lower bound can prove a ceiling was exceeded, but cannot prove a below-ceiling pass until every gene ID is resolved. The workflow writes checksums, reference counts, per-guide observations, and unknown statuses to `transcript_seed/guide_observations.json`.
